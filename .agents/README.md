# 에이전트 공용 작업 공간

여기는 WorkBoard를 작업하는 에이전트의 인수인계와 협업 기록을 두는 공간입니다. 제품 요구사항은 `docs/`, 저장소 규칙은 루트 `AGENTS.md`, 실제 코드와 검증 결과는 Git 커밋을 기준으로 확인합니다. 이 공간의 상태 문서는 최신 상태를 찾는 안내문이며 Git·Notion의 실제 상태를 대체하지 않습니다.

## 작업 시작

1. 루트 `AGENTS.md`, `README.md`, 관련 `docs/`를 읽습니다.
2. `git status`, 현재 브랜치, 최근 커밋과 원격 상태를 확인합니다.
3. [현재 상태](STATUS.md)를 읽고, 내용이 Git과 다르면 실제 상태를 확인한 뒤 문서를 고칩니다.
4. 같은 파일을 다른 작업자가 수정 중인지 확인하고, 기능 작업은 별도 브랜치에서 진행합니다.
5. Notion 프로젝트 문서와 전용 작업 이력·백로그를 확인할 때는 루트 `AGENTS.md`의 위치를 사용합니다. 외부 기록을 바꾸기 전에는 실제 데이터 소스와 중복 항목을 확인합니다.

## 작업 인수인계

- 논리적 작업 단위가 끝나면 `sessions/`에 `YYYY-MM-DD-주제.md` 파일을 남깁니다. 같은 날짜에 같은 주제의 작업이 있으면 짧은 식별자를 덧붙입니다.
- [양식](sessions/TEMPLATE.md)의 목표, 변경 파일, 실행한 검증, Git 상태, 미완료 사항을 실제 근거로 채웁니다. 실행하지 않은 테스트나 push를 완료로 적지 않습니다.
- `STATUS.md`는 기본 브랜치에 반영된 기준만 갱신합니다. 기능 브랜치의 변경은 세션 기록과 Notion 개발 작업 이력에서 추적합니다.
- 저장소 밖의 비밀값, 실제 업무 데이터, 사용자 식별자, NAS 경로는 이 공간에도 기록하지 않습니다.
- push, PR, 배포는 루트 `AGENTS.md`의 승인 범위를 따릅니다.

## 충돌 방지

여러 에이전트가 같은 브랜치나 같은 파일을 동시에 편집하지 않도록 작업 범위를 먼저 확인합니다. 다른 에이전트의 미커밋 변경은 되돌리지 않습니다. 브랜치 병합 전에는 최신 `main`과 차이를 확인하고 필요한 검증을 다시 수행합니다.
