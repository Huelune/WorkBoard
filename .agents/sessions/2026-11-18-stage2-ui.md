# 2단계 데스크톱 화면 구현

- 날짜: 2026-11-18
- 담당 작업 세션: WorkBoard 2단계 구현
- 브랜치 및 기준 커밋: feat/stage2-ui, 기준 dcc6ebc(1단계 브랜치 끝)
- 작업 상태: 완료(브랜치에만 있음, main 미반영)

## 목표와 범위

1단계 Service 위에 PySide6 창을 만든다. 담당자별 묶음 목록, 내 업무, 완료 근거 입력, 확인 대기, 현황·속도(담당자별·프로젝트별)를 포함한다. 가져오기와 충돌 표시는 범위 밖이다.

## 변경 사항과 주요 파일

- docs/superpowers/specs/2026-11-18-stage2-ui-design.md: 설계와 결정
- src/workboard/config.py: 로컬 설정(DB 위치, 사용자 ID)
- src/workboard/ui: 기본 창, 업무 목록과 상세, 확인 대기, 현황·속도, 대화상자, 한글 라벨
- src/workboard/services: 편집자 여부 조회, 묶음 요약의 범위·분류 필터
- pyproject.toml: PySide6 의존성 추가

## 실행한 검증

- 가상 환경(PySide6 6.12.0, Python 3.14)에서 전체 테스트 80개 통과
- PySide6 없는 Python에서 65개 통과, 화면 테스트 15개 건너뜀
- 예시 데이터로 창을 그려 캡처한 그림을 눈으로 확인(목록, 확인 대기, 현황·속도)
- 사람이 직접 창을 눌러 보는 확인은 하지 않았다(한글 입력, 대화상자 흐름, 고해상도, 키보드 이동).

## Git 및 외부 반영

- 로컬 브랜치 feat/stage2-ui에만 커밋. push, PR 없음. Notion 기록은 갱신하지 않았다.

## 남은 사항과 다음 단계

- 칸 안에서 바로 고치기, 일괄 변경, 정렬은 넣지 않았다.
- 업무 추가는 업무 생성과 배정을 차례로 호출한다. 배정 쪽 입력은 먼저 검사하지만 한 트랜잭션은 아니다.
- 표시 이름이 없어 담당자는 ID로 보인다.
- 사용할 PC에 PySide6를 설치하는 방법(사내 반입 포함)은 정해지지 않았다.
