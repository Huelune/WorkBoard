# WorkBoard 제품 계획

## 목표와 해결하려는 문제

하나의 엑셀에서 업무 대상, 담당자, 기한, 진행도를 관리하면 여러 사람이 동시에 갱신하기 어렵다. WorkBoard는 엑셀형 목록과 프로젝트 현황을 제공하면서 PC별 로컬 작업과 NAS를 통한 공유를 지원한다.

## 대상 사용자와 사용 흐름

- 프로젝트 편집자: 프로젝트와 업무 분류를 만들고, 대상·담당자·기한을 지정한다.
- 담당자: 내 업무를 보고 상태·진행도·결과를 입력한다.
- 조회 사용자: 프로젝트와 분류별 완료·보류·지연 현황을 확인한다.

## 공통 업무 모델

프로젝트 아래에 선택적인 범위와 분류를 두고, 업무 항목을 등록한다. 업무 항목은 UUIDv4 ID로 식별한다. 같은 제목도 서로 다른 범위에 반복될 수 있다. 담당자, 기한, 상태, 진행도, 결과는 항목별로 독립적이다.

첫 사용 사례인 검증 업무에서는 프로젝트 → 대상 코드 버전 → 검증 분야 → Codebeamer 대상 함수 순서로 묶는다. 프로젝트 + 버전 + 분야 + Codebeamer 항목 ID 조합은 검증 템플릿의 중복 확인 기준이다. 다른 업무 템플릿에는 이 조합을 강제하지 않는다.

## 첫 버전 범위

1. 엑셀형 목록: 검색, 정렬, 필터, 셀 편집, 일괄 변경.
2. 내 업무와 프로젝트 현황: 전체·완료·보류·기한 초과 건수.
3. 담당자·기한·상태·진행도·결과 및 변경 이력.
4. 엑셀 가져오기 미리보기와 CSV 내보내기.
5. 로컬 저장과 NAS 공유 상태 구분 및 충돌 표시.
6. 업무별 외부 시스템 참조 ID와 링크.
7. 검증 업무용 분류 및 가져오기 템플릿.

## 제외 범위

Codebeamer API 자동 조회·결과 역전송, 채팅, 첨부, 공수 예측, 복잡한 승인 흐름은 첫 버전에서 제외한다.

## 상태 규칙 초안

기본 상태는 미시작, 진행 중, 보류, 완료다. 미시작은 진행도 0%, 완료는 진행도 100%, 보류는 사유 입력이 필요하다. 검증 업무의 결과는 통과, 실패, 해당 없음으로 구분할 수 있다. 결과 필드는 일반 업무에서는 선택 항목이다. 검토 대기는 실제 승인 절차가 확인되면 추가한다.

## 저장소와 모듈 책임

- domain: 공통 업무 식별과 업무 규칙.
- services: 권한 및 입력 검증과 트랜잭션.
- storage: 로컬 SQLite와 마이그레이션.
- sync: NAS JSON 스냅샷 생성·검증·전송·수신.
- ui: 엑셀형 목록과 현황 표시. 저장소에 직접 쓰지 않는다.

실행 진입점은 `workboard` 명령이다. 설정은 로컬 파일 또는 환경 변수로 제공하고 실제 설정은 커밋하지 않는다.

## 데이터 흐름과 외부 연동

화면 → Service → 로컬 SQLite + 전송 대기 목록 → NAS JSON 스냅샷 → 다른 PC의 로컬 SQLite. Codebeamer는 첫 버전에서 링크와 ID만 보관한다.

## 보안과 민감 정보

NAS 폴더 접근 권한을 사용자별로 분리한다. 담당자는 자신의 진행 내용만 쓰고, 타인의 진행 내용은 조회만 한다. 실제 업무 데이터, NAS 주소, 인증 정보는 저장소와 예시에 포함하지 않는다.

## 초기 위험과 결정 필요 항목

- 현재 엑셀 열과 한 행의 실제 의미를 확인해야 한다.
- 동일 계정의 여러 PC 동시 편집 정책이 필요하다. 첫 버전은 한 대의 쓰기 PC를 권장한다.
- NAS 기반 공유는 즉시 반영을 보장하지 않는다.
- 검증 업무의 Codebeamer 항목 ID가 버전별로 어떤 의미인지 확인해야 한다.
- NAS 접근 권한과 백업·복구 운영 절차가 필요하다.

## Git과 문서 운영

기본 브랜치는 main이다. 기능은 별도 브랜치에서 구현하고 검증 후 PR로 병합한다. 한글 Conventional Commits를 사용한다. 제품 기준 문서는 이 파일, 저장 세부 설계는 storage-design.md, 검증 기준은 validation.md에서 관리한다.
