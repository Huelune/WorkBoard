# 3단계 설계: 엑셀에서 업무 가져오기

작성일: 2026-11-18. 상태: 승인 대기.

## 의도

지금 엑셀로 관리하던 업무를 WorkBoard로 옮긴다. 편집자가 엑셀 표를 읽혀 업무와 배정을 한꺼번에 등록한다. 엑셀 파일은 회사 문서 보안(DRM)으로 암호화돼 있어, 로그인한 PC의 엑셀로만 열린다.

## 사용자가 정한 것 (2026-11-18)

- 엑셀은 Windows에 설치된 엑셀로 연다. 파일을 직접 풀어 읽는 방식은 쓰지 않는다.
- "잠겨 있다"는 것은 문서 보안(DRM)이다.
- 업무와 배정만 가져온다. 엑셀에 적힌 진행도와 상태는 가져오지 않는다. 진행은 담당자 본인이 들어와 입력한다.
- 표는 대체로 한 줄이 업무 하나와 담당자 한 명이다. 제목 줄이 맨 위가 아닐 수 있다.

## 목표

- 엑셀 표를 읽어 열을 맞추고, 적용하기 전에 무엇이 등록되고 무엇이 빠지는지 건수로 보여 준다.
- 같은 표를 다시 가져와도 같은 업무가 두 번 생기지 않는다.
- 읽은 줄 수 = 새로 등록 + 이미 있음 + 오류 + 빈 줄이 항상 맞는다.
- 원본 파일은 바꾸지 않는다.

## 하지 않는 것

- 진행도·상태·결과 가져오기, CSV 내보내기, 엑셀로 되돌려 쓰기.
- 한 칸에 담당자가 여러 명인 줄을 나누는 것, 병합된 칸을 아래로 채우는 것.
- 엑셀 파일을 직접 풀어 읽는 것(DRM 파일은 읽을 수 없다).

## 이렇게 되면 실패다

- 가져오기가 엑셀 파일을 고치거나 저장한다.
- 오류가 있는 줄이 말없이 빠지거나, 말없이 등록된다.
- 화면 밖(기록 파일, 오류 안내)으로 엑셀 칸의 원문이 나간다.
- 편집자가 아닌 사람이 가져오기로 남의 업무를 등록한다.

## 접근 방식

| 선택지 | 판단 |
| --- | --- |
| 설치된 엑셀을 조종해 읽기(PySide6의 Windows 연동 기능) | **채택.** 새 패키지가 필요 없다. 이 PC의 엑셀 16으로 읽기 전용 열기와 값 읽기를 시험해 확인했다 |
| pywin32로 엑셀 조종 | 기각. 같은 일을 하는데 사내에 반입할 패키지가 하나 더 는다 |
| openpyxl 등으로 파일 직접 읽기 | 기각. DRM으로 암호화된 파일은 내용을 읽을 수 없다 |
| 실행 중인 엑셀에 붙어 열린 문서 읽기 | 보류. 시험에서 붙는 데 실패했다. 필요해지면 다시 본다 |

엑셀은 **보이는 창으로** 띄워 읽기 전용으로 연다. 문서 보안 프로그램이 묻는 창이 있으면 사용자가 보고 답할 수 있어야 하기 때문이다. 읽은 뒤에는 그 문서를 저장하지 않고 닫고, 가져오기가 띄운 엑셀도 닫는다.

조종이 막힌 PC를 위해 **붙여 넣기**를 두 번째 길로 둔다. 엑셀에서 칸을 복사해 가져오기 창에 붙여 넣으면 같은 흐름으로 이어진다.

## 내가 정한 것 (틀리면 고친다)

### 흐름

1. 편집자가 "가져오기"를 연다. 파일을 고르거나 붙여 넣는다.
2. 표의 앞부분을 보여 준다. 제목 줄을 고른다(자동으로 짐작하고 고칠 수 있다).
3. 열을 맞춘다: 제목(필수), 프로젝트의 두 칸(필수), 담당자(필수), 기한, 외부 참조 ID, 외부 링크. 열 제목으로 짐작해 미리 채운다. 맞춘 결과는 프로젝트별로 기억한다.
4. 미리보기: 새로 등록, 이미 있음, 오류, 빈 줄의 건수와 줄별 사유를 보여 준다. 새로 만들어질 두 칸의 항목도 보여 준다.
5. 확인하면 한 트랜잭션으로 적용한다. 오류 줄은 빠지고, 버튼에 "새 업무 N건 등록(오류 M건 제외)"라고 적는다.

### 줄을 읽는 규칙

- 제목이 빈 줄은 빈 줄로 센다.
- 담당자 칸의 글자는 구성원의 ID 또는 표시 이름과 같아야 한다. 맞는 구성원이 없으면 오류다. 엑셀에는 보통 이름이 적혀 있으므로, 편집자가 먼저 관리 화면에서 구성원에 표시 이름을 넣어 둔다.
- 두 칸의 값이 프로젝트에 없는 이름이면 적용할 때 새 항목으로 만든다. 삭제된 항목과 같은 이름이면 오류다.
- 기한은 엑셀의 날짜 칸이면 그대로, 글자면 `2026-01-15`, `2026.1.15`, `2026/01/15` 꼴을 받아들인다. 그 밖은 오류다. 비어 있으면 기한 없음이다.
- 외부 링크는 http와 https만 받는다.
- 숫자 칸은 글자로 바꾼다(`12.0`은 `12`).

### 이미 있음을 가리는 기준

- 외부 참조 ID가 있으면: 같은 프로젝트에서 두 칸의 항목, 외부 참조 ID, 담당자가 모두 같은 살아 있는 업무.
- 없으면: 두 칸의 항목, 제목, 담당자가 모두 같은 살아 있는 업무.
- 같은 표 안에서 기준이 겹치는 둘째 줄부터도 "이미 있음"이다.
- 취소된 배정과 삭제된 업무는 비교에서 뺀다.

`docs/product-plan.md`의 "프로젝트 + 버전 + 분야 + 외부 항목 ID" 기준에 담당자를 더한 것이다. 한 업무에 담당자가 여럿이면 줄이 여럿이기 때문이다.

### 권한

가져오기는 프로젝트 편집자만 한다. 구성원의 본인 업무 등록은 기존의 "업무 추가"로 한다.

### 구조

- `import_export/table.py`: 표 다루기. 제목 줄 짐작, 열 짐작, 줄을 업무 후보로 바꾸기, 날짜와 숫자 정리. 화면과 엑셀에 기대지 않는다.
- `import_export/excel.py`: 설치된 엑셀로 파일을 열어 표를 돌려준다. 실패는 종류로만 알린다(엑셀 없음, 열지 못함, 응답 없음, 표가 너무 큼).
- `services`: `plan_import`(쓰지 않고 줄별 판정을 돌려줌)와 `apply_import`(같은 판정으로 한 트랜잭션에 적용). 열 맞춤 기억은 로컬 DB에 둔다(스키마 6버전).
- `ui/import_dialog.py`: 위 흐름의 창.

### 크기 제한

한 번에 5,000줄, 60열까지 읽는다. 넘으면 읽지 않고 알린다.

## 테스트로 확인할 것

- 표 다루기: 제목 줄 짐작, 열 짐작, 날짜 꼴, 숫자 정리, 빈 줄.
- 판정: 새로 등록, 이미 있음(외부 참조 기준과 제목 기준, 표 안의 겹침), 오류 사유별, 건수의 합이 읽은 줄 수와 같음.
- 적용: 한 트랜잭션, 새 항목 생성, 다시 가져오면 새로 등록이 0건.
- 권한: 편집자가 아니면 거부.
- 화면: 붙여 넣기부터 적용까지, 열 맞춤 기억.
- 엑셀 읽기: 이 PC의 엑셀로 지어낸 파일을 읽는 시험. 엑셀이 있어야 하므로 평소 테스트에서는 건너뛰고 따로 돌린다.

## 확인하지 못하는 것

문서 보안이 걸린 실제 파일을 엑셀 조종으로 읽을 수 있는지는 이 PC에서 확인할 수 없다. 보안 프로그램이 조종이나 복사를 막을 수 있다. 회사 PC에서 `todo.md`의 절차로 확인하고, 막혀 있으면 붙여 넣기도 되는지 본다. 둘 다 막히면 방식을 다시 정해야 한다.
