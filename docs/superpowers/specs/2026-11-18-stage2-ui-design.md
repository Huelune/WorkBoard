# 2단계 설계: 데스크톱 화면

작성일: 2026-11-18. 상태: 승인됨(화면 시안 세 가지와 PySide6 선택을 사용자가 확정).

## 의도

1단계 Service 위에 실제 창을 만든다. 2026-11-18에 확정한 시안(담당자별 묶음 목록, 근거 입력과 완료 확인, 담당자별·프로젝트별 속도)을 따른다. 화면이 복잡해 보이지 않는 것이 사용자의 핵심 요구다.

## 접근 방식

| 선택지 | 판단 |
| --- | --- |
| PySide6 | **사용자가 선택.** 목록 칸 안의 진행 막대와 색 표시를 그릴 수 있다. PC마다 설치가 필요하다 |
| tkinter | 기각. 추가 설치는 없지만 목록 칸에 글자만 넣을 수 있어 시안의 막대가 빠진다 |

## 화면

- 위쪽 줄: 프로젝트·범위·분류 선택, 새 프로젝트, 관리(편집자·범위·분류 추가), 공유 대기 건수, 무결성 경고.
- 왼쪽 메뉴: 업무 목록, 내 업무, 확인 대기(건수), 현황·속도.
- 업무 목록: 기본은 담당자별로 묶어 접은 상태. 묶음 줄에 건수, 평균 진행 막대, 챙길 것. 묶기 기준(담당자별·분류별·묶지 않음), 확인된 완료 숨기기(기본 켬), 검색. 펼친 행은 반려됨, 기한 초과, 그 밖의 순서. 오른쪽에 상세(정의, 근거, 이력, 확인 기록).
- 내 업무: 내 배정을 묶지 않고 보여 준다. 진행 입력 창에서 완료를 고르면 근거를 요구한다.
- 확인 대기: 근거를 보고 확인 또는 반려(사유 필수). 편집자만 버튼을 쓸 수 있다.
- 현황·속도: 현황 숫자, 담당자별 탭(이 프로젝트 또는 모든 프로젝트), 프로젝트별 탭. 기간은 최근 4·8·12주. 주별 추이는 글자 막대로 그린다.

## 내가 정한 것

- "나"는 기본으로 OS 로그인 이름이고 로컬 설정 파일의 `[user] id`로 바꾼다. 0단계의 사용자 식별 가정을 따른다.
- 설정 파일은 `WORKBOARD_CONFIG` 환경 변수가 가리키는 파일, 없으면 홈 폴더의 `.workboard/config.toml`이다. DB 기본 위치는 홈 폴더의 `.workboard/workboard.db`다.
- 정의 편집은 대화상자로 한다. 칸 안에서 바로 고치기와 일괄 변경은 이번에 넣지 않는다.
- 업무 추가는 업무와 첫 배정을 한 창에서 받는다. 배정 없는 업무는 목록에 보이지 않기 때문이다.

## 직접 써 본 뒤 바꾼 것 (2026-11-18)

사용자가 창을 눌러 보고 업무 추가가 불편하다고 했다. 요청은 세 가지다: 편집자는 담당자를 목록에서 고른다, 일반 사용자는 자기가 자동으로 담당자가 된다, 여러 업무를 한 번에 등록한다.

- 프로젝트 구성원을 둔다(스키마 2버전). 편집자가 ID와 표시 이름으로 추가하고, 배정받은 사람은 자동으로 구성원이 된다. 화면은 표시 이름이 있으면 그것을 보여 준다.
- 편집자의 업무 추가 창은 구성원 목록에서 담당자를 고른다. 목록에 없는 ID를 직접 입력해도 되고, 그러면 구성원으로 들어간다.
- 편집자가 아닌 구성원도 업무를 추가할 수 있다. 담당자는 본인으로 고정된다. "정의는 편집자가 관리한다"는 규칙의 예외이며 AGENTS.md에 적었다.
- 업무 추가 창은 입력 방식을 고를 수 있다. 기본은 줄마다 제목·외부 참조 ID·링크를 적고 + 버튼으로 줄을 늘리는 방식이고, 다른 탭은 여러 줄을 붙여 넣는 칸이다. 보이는 탭의 내용만 등록한다. Enter는 저장이 아니라 다음 줄 추가다.
- 붙여 넣는 칸은 여러 줄이다. 한 줄에 하나씩 등록하고, 탭으로 나뉜 둘째·셋째 칸은 외부 참조 ID와 링크로 읽는다. 전부 한 트랜잭션이라 한 줄이라도 잘못되면 아무것도 저장하지 않는다.
- 본인이 등록한 업무는 상세에 표시하고, 담당자별 속도 표에 "본인 등록" 건수를 둔다. 작은 일을 여러 개 등록해 건수를 늘리는 것을 드러내기 위해서다. 확인된 완료가 되려면 여전히 편집자의 확인이 필요하다.
- 가져오기(3단계)와 충돌 표시(4단계)는 메뉴에 넣지 않는다.
- 오류는 종류와 할 일만 한글로 보여 준다. 저장 실패의 원문은 화면에 찍지 않는다.
- 다른 사람이 입력한 글자는 상세 화면에 넣기 전에 HTML로 해석되지 않게 바꾼다.
- 화면은 Service만 부른다. 1단계 Service에 조회 두 가지를 보탠다: 편집자 여부, 묶음 요약의 범위·분류 필터.

## 검증

- 창을 화면 없이 띄우는 자동 테스트: 묶음과 필터, 상세, 진행 입력, 확인·반려, 속도 표, 무결성 경고, 권한 오류 표시.
- 실제 창을 캡처해 시안과 비교한다.
- 사람이 직접 눌러 보는 확인(한글 입력, 고해상도, 키보드 이동)은 사용자 PC에서 한다.
- "범위"와 "분류"라는 말이 화면에서 애매하다는 의견이 있어, 프로젝트마다 두 칸의 이름을 정하게 했다(스키마 3버전). 기본은 "대상 버전"과 "업무 분야"이고 편집자가 "관리 → 칸 이름 바꾸기"에서 바꾼다. 모든 프로젝트의 이름을 한 번에 바꾸는 방법은 검증 업무에만 맞는 말이 공통 도구에 박히므로 택하지 않았다.
