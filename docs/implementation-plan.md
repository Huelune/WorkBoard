# 전체 작업 계획

이 문서는 WorkBoard 첫 사용 가능 버전까지의 구현 순서와 완료 기준이다. 날짜와 담당자는 아직 배정하지 않는다. 1단계(도메인·로컬 저장)는 0단계 결정표의 가정을 그대로 써서 구현했고, 가정이 바뀌면 고친다. 2단계(데스크톱 화면)는 PySide6로 구현했다. 칸 안에서 바로 고치기와 일괄 변경은 아직 없고 대화상자로 편집한다. 3단계 가운데 엑셀 가져오기를 구현했다. 문서 보안(DRM) 파일이라 설치된 엑셀로 읽고, 막히면 복사한 칸을 붙여 넣는다. CSV 내보내기는 아직 없다. 4단계 이후의 제품 기능은 구현 전이다.

## 목표와 기준

- 공통 업무를 프로젝트별 엑셀형 목록으로 조회·편집한다.
- 여러 PC에서 각자의 변경을 로컬에 먼저 저장하고 NAS JSON 스냅샷으로 공유한다.
- 검증 업무는 첫 템플릿이다. 코드 버전, 모델·단위·통합 분야, Codebeamer 대상 함수는 이 템플릿에만 적용한다.
- 로컬 저장, 공유 대기, 공유 완료, 충돌을 사용자에게 구분해 보여준다.

## 구현 단계

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0. 입력 자료 확정 | 현재 엑셀의 열과 익명화된 행, 업무 상태·결과 용어, 담당자 식별 방식, NAS 운영 조건을 확인한다. | 한 행의 의미와 가져오기 매핑표가 정해지고, 미결정 항목의 책임자와 결정이 기록된다. |
| 1. 도메인·로컬 저장 | 프로젝트, 범위, 분류, 업무, 배정, 진행 이력, 전송 대기와 마이그레이션을 구현한다. 권한과 입력 규칙을 Service에서 검증한다. | NAS 없이 업무 생성·배정·진행 갱신이 유지되고, 재시작 후에도 조회된다. 권한 위반과 잘못된 입력은 저장되지 않는다. |
| 2. 데스크톱 화면 | 프로젝트 선택, 엑셀형 목록, 내 업무, 상세 편집, 현황·필터, 저장 상태 표시를 구현한다. | 키보드 중심으로 검색·정렬·편집이 가능하고, 로컬 저장 성공이 즉시 보인다. 화면은 Service만 호출한다. |
| 3. 엑셀 입출력 | 가져오기 미리보기, 열 매핑, 누락·중복 검사, 적용 전후 건수 대조와 CSV 내보내기를 구현한다. | 익명화된 기존 양식으로 오류를 먼저 확인하고, 중복 적용 없이 재가져올 수 있다. |
| 4. NAS 공유 | 프로젝트 정의와 사용자별 진행 JSON 스냅샷, 전송 대기 재시도, 수신 검증, 충돌 표시를 구현한다. | NAS 중단 중 로컬 작업이 보존되고, 재연결 후 다른 PC에 반영된다. 충돌·손상 파일은 자동 덮어쓰지 않는다. |
| 5. 운영 검증·배포 | 실제 PC와 NAS에서 동시 사용, 권한, 백업·복구, 설치·업그레이드와 장애 복구를 확인한다. | 아래 출시 기준을 실제 환경에서 통과하고, 운영 절차와 알려진 제한을 문서화한다. |

각 단계는 코드·테스트·사용 흐름을 함께 마무리한다. 다음 단계에 필요한 계약이 정해지면 진행할 수 있으나, 미완료 단계를 완료로 표시하지 않는다.

## 화면 구성

1. 프로젝트 선택과 범위·분류 필터: 프로젝트, 코드 버전 또는 일반 범위, 업무 분류를 선택한다.
2. 업무 목록: 기본은 담당자별로 묶어 접은 상태다. 담당자 한 줄에 건수, 평균 진행 막대, 챙길 것(확인 대기·반려·기한 초과)을 보여 주고 펼치면 할 일이 나온다. 묶는 기준은 담당자별, 분류별, 묶지 않음이다. 확인된 완료는 기본으로 숨긴다. 검색·정렬·필터·셀 편집·일괄 변경을 지원한다.
3. 내 업무: 자신에게 배정된 행과 기한 초과·보류 항목을 빠르게 찾는다. 완료로 바꿀 때 근거 입력 창이 뜬다.
4. 상세 패널: 업무 정의, 배정, 완료 근거, 진행 이력, 확인 기록, 충돌 정보를 분리해 보여준다. 수정 권한이 없는 값은 읽기 전용으로 표시한다.
5. 확인 대기: 편집자가 완료 신고의 근거를 보고 확인하거나 반려한다. 자기가 담당한 업무는 나오지 않는다.
6. 현황·속도: 전체·확인된 완료·확인 대기·보류·기한 초과 건수와 분류별 집계, 담당자별 속도 탭, 프로젝트별 속도 탭을 보여준다. 두 탭 모두 주별 추이를 둔다. 값은 저장된 원본 행과 이력에서 계산한다.
7. 가져오기 미리보기와 공유 상태: 적용 전 오류와 중복을 검토하고, 로컬 저장·공유 대기·공유 완료·충돌을 구분한다.

첫 버전은 데스크톱 전용이다. 화면 기술은 PySide6을 권장하며, 선택 전 배포 대상 OS와 설치 제약을 확인한다. Gantt, 채팅, 첨부, 알림, Codebeamer API 양방향 연동은 첫 버전에서 다루지 않는다.

## 검증과 출시 기준

- 도메인·Service: UUID 식별, 상태·진행도·기한 규칙, 권한, 진행 이력의 원자성을 자동 테스트한다.
- 저장소: 마이그레이션, 재시작 후 보존, 전송 대기 재시도와 중복 수신을 테스트한다.
- 화면: 실제 데스크톱에서 목록 편집, 필터, 권한별 읽기 전용 표시와 오류 피드백을 확인한다.
- 가져오기: 누락·중복·잘못된 날짜·동일 제목 다른 범위의 사례로 원본 행 수와 적용 수를 대조한다.
- 공유: NAS 오프라인, 재연결, 두 PC 변경, 정의 충돌, 손상 스냅샷과 백업 복구를 실제 환경에서 확인한다.
- 출시: 위 흐름을 통과하고 사용자 설치·설정·복구 문서가 준비되면 첫 사용 가능 버전으로 표시한다.

## 결정이 필요한 입력

| 항목 | 현재 가정 | 확정에 필요한 근거 |
| --- | --- | --- |
| 엑셀 한 행 | 한 업무 대상과 한 담당자의 배정 행 | 익명화된 실제 열·행 예시 |
| 진행도 | 담당자가 0~100을 입력하며 상태와 맞는지 검증 | 현재 엑셀의 계산식과 입력 관행 |
| 복수 담당자 | 한 업무에 별도 배정 행을 둔다 | 실제 공동 담당 사례 |
| Codebeamer ID | 버전·분야 안에서 중복 검사에 사용한다 | 항목 ID의 버전 간 재사용 여부 |
| 사용자 식별 | 팀 내 고정 ID를 사용하고 표시 이름은 별도 관리한다 | 운영 계정과 NAS 권한 정책 |
| 동시 편집 | 프로젝트 정의 게시 때 개정 번호와 잠금을 확인한다 | NAS 파일 공유 방식과 잠금 동작 |
| 대상 OS | 데스크톱 배포 환경 확인 전 미확정 | 사용 PC의 OS·설치 권한 |

이 입력은 기능 구현 전에 확정한다. 결론이 나지 않아도 다른 단계의 독립 작업은 진행할 수 있지만, 데이터 형식이나 충돌 정책을 추정해 확정 기능으로 구현하지 않는다.
